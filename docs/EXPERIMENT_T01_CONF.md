> **คำถามที่ทดลองเพื่อตอบ:** สัญญาณของคลาส `defect` "ไม่มี" จริง หรือ "มีแต่จมอยู่ใต้ threshold"
> เอกสารอ้างอิง: [REQUIREMENTS_STAKEHOLDER_ANALYSIS.md](./REQUIREMENTS_STAKEHOLDER_ANALYSIS.md) — FR-33 / T-01 (เงื่อนไขก่อนเริ่ม T-08)
>
> **วิธีรันซ้ำ:** `label_tool/` → `.venv\Scripts\python.exe -m backend._experiment_conf 20`
> (arg ที่ 2 เป็นต้นไปคือค่า conf ที่อยากลอง เช่น `... 20 0.03 0.05 0.07`)

| รายการ | ค่า |

## ข้อสรุป

### 1. recall ขยับ — และขยับมาก (ตอบคำถามหลักของ T-01)

`defect` recall ที่ conf ต่าง ๆ: **0.00** (0.25) → **0.04** (0.10–0.15) → **0.26** (0.05) → **0.36** (0.01)

สัญญาณของ `defect` **มีอยู่จริง แต่จมอยู่ใต้ threshold ที่ใช้อยู่** ที่ conf 0.25 (ค่า default ของ `/api/evaluate` และของปุ่ม auto-label) โมเดลไม่คืนกล่อง `defect` ที่ถูกต้องเลยแม้แต่กล่องเดียวจาก 50 กล่อง — ตัวเลข "F1 0.04–0.07" ที่บันทึกไว้เดิมจึงเป็นการวัดที่ threshold ผิดค่า ไม่ใช่เพดานของโมเดล

### 2. ค่าที่ดีที่สุดของ `defect` คือ conf ≈ 0.05 และตกชันทั้งสองฝั่ง

F1 ของ `defect` เป็นยอดโด่งแคบ ๆ ที่ 0.05 (F1 0.248) — ต่ำกว่านั้น precision พังเพราะ FP ระเบิด (ที่ 0.01 มี FP 378 กล่อง), สูงกว่านั้น recall หายไปเกือบหมดภายใน 0.02 หน่วย นี่ไม่ใช่ค่าที่ผู้ใช้ควรต้องหาเจอเองด้วย slider

### 3. สองคลาสต้องการ threshold คนละค่า และนี่คือ quick win ที่ยังไม่ได้เก็บ

| คลาส | conf ที่ให้ F1 สูงสุด | F1 |
|---|---|---|
| `defect` | 0.05 | 0.248 |
| `good_part` | 0.25 | 0.818 |

ค่า conf **ค่าเดียวทั้งระบบ** บังคับให้ต้องเลือกว่าจะทิ้งคลาสไหน — ที่ 0.25 `defect` เป็นศูนย์, ที่ 0.05 `good_part` เสีย F1 ไป 0.23

**ทำแล้ว:** `/api/evaluate`, `/api/autolabel`, `/api/predict` รับ `conf_by_class` (dict คลาส → threshold) ได้แล้ว ค่าว่าง = พฤติกรรมเดิมทุกประการ ดูตารางถัดไปว่าได้ผลทั้งสองคลาสพร้อมกันจริง

### 4. หลักฐานสนับสนุนสมมติฐาน A2 (ปัญหาคือ scale ไม่ใช่ diversity)

ขนาดกล่อง median เทียบพื้นที่ภาพ:

| คลาส | median box area |
|---|---|
| `defect` | **2.09%** ของภาพ |
| `good_part` | 43.45% ของภาพ |

ต่างกันประมาณ **20 เท่า** ที่ imgsz=640 กล่อง defect ขนาด 2% ของภาพกินพื้นที่ราว 90×90 px ก่อน resize และเหลือไม่กี่สิบพิกเซลบน feature map ที่ SAVPE ดึง embedding — สอดคล้องกับสมมติฐานว่าปัญหาอยู่ที่ resolution ดังนั้น **ลำดับ T-08 (crop) ก่อน T-11 (NN-matching) ในเอกสารหลักยังถูกต้อง**
