### ข้อยกเว้นที่ตั้งใจ — ต่างจากแผนใน §4

ก. **สวิตช์ปิด shortcut อยู่ในกล่อง Keyboard shortcuts ไม่ได้อยู่ข้าง *Plain language***
   app bar มี checkbox, ปุ่ม และ chip อยู่แล้ว การเพิ่ม checkbox ตัวที่สองทำให้แน่นเกินไป
   ปุ่มคีย์บอร์ดบน app bar บอกสถานะแทน (จุดสีเหลืองเมื่อปิด และ `aria-label` พูดออกมา)

ข. **`overflow-x` เป็น `clip` ไม่ใช่ลบทิ้ง** `clip` ไม่ทำให้ `<body>` กลายเป็น scroll
   container จึงไม่ไปพัง `position: sticky` ของ app bar แบบที่ `hidden` ทำ แต่ทั้งคู่ยัง
   **ปิดบัง** บั๊ก reflow เหมือนกัน ต้นเหตุที่รู้แล้วคือ tooltip ล้นขอบขวา ซึ่งถูก clamp
   ด้วย `max-width: min(260px, calc(100vw - 24px))` แล้ว — ที่เหลือ **ต้องตรวจ 320px ด้วยมือ**
   ถึงจะปิด 1.4.10 ได้จริง

ค. **พื้นตัวอักษร 12px สำหรับข้อความ UI, 11px สำหรับ micro-label** แผนเขียนว่า
   "ไม่มี rule ไหนต่ำกว่า 12px" แต่ตัวที่เหลือที่ 11px คือ label ตัวใหญ่เว้นระยะ
   (`.brand-sub`, `.metric-k`, `.tag-soon`, `.step-idx`, `.swatch .key`, `.gallery-name`)
   ไม่ใช่ body text — WCAG ไม่ได้กำหนดขนาดขั้นต่ำอยู่แล้ว ฐานขึ้นจาก 13.5px เป็น 14px ตามแผน

ง. **tooltip บน chip ที่กดไม่ได้ ยังเปิดด้วย hover เท่านั้น** ข้อความไปถึง screen reader
   ผ่าน `aria-describedby` แล้ว แต่คนที่ใช้คีย์บอร์ดและมองเห็นจะเปิดมันไม่ได้
   ทางที่ถูกคือเปลี่ยน chip พวกนั้นเป็น `Term`/`HelpDot` ซึ่งเป็นปุ่ม — ยังไม่ได้ทำ

จ. **crosshair สำหรับวาดกล่องด้วยคีย์บอร์ด ถูกถอดออกหลังส่งมอบ** (คำขอของเจ้าของงาน
   2026-08-31) ตอนนี้จึงเป็นแบบนี้:

   | ทำอะไรกับกล่อง | เมาส์ | คีย์บอร์ด |
   |---|---|---|
   | เลือก | คลิกขอบ | `Tab` |
   | ย้าย / ย่อขยาย | ลาก | ลูกศร / `Alt`+ลูกศร |
   | ลบ | ปุ่ม × | `Delete` |
   | **วาดใหม่** | ลาก | **ไม่ได้** |

   ผลตามเกณฑ์: **2.5.7 ยังผ่าน** — การลากเพื่อย้ายและย่อขยายมีทางเลือกที่ไม่ต้องลากครบแล้ว
   แต่ **2.1.1 (Level A) กลับมาตกสำหรับการสร้างกล่อง** คนที่ใช้คีย์บอร์ดอย่างเดียวจะ
   label ภาพแรกไม่ได้ · เป็นการแลกที่ตัดสินใจแล้วโดยรู้ราคา ไม่ใช่ของที่หลุด —
   ถ้าจะปิดข้อนี้จริงต้องมีทางสร้างกล่องที่ไม่ใช่การลาก เช่น ปุ่ม "เพิ่มกล่องกลางภาพ"
   แล้วใช้ลูกศรจัดตำแหน่ง ซึ่งเป็นโค้ดน้อยกว่า crosshair ที่ถอดออกไปมาก

## 2. สิ่งที่ดีอยู่แล้ว — ห้าม redesign ทับ

นี่คือเหตุผลที่คะแนนเป็น 60 ไม่ใช่ 30 แผนใน §4 ต้องรักษาของพวกนี้ไว้ทั้งหมด

- **ตัวหนังสือ (copy)** — `PoolPanel.tsx:56-77` อธิบายว่าการแก้ label ที่โมเดลทำ **ไม่ได้**
  แปลว่าโมเดลเรียนรู้ไปด้วย ซึ่งเป็นเรื่องที่คนเข้าใจผิดมากที่สุดในเครื่องมือนี้ และอธิบาย
  *ณ จังหวะที่มันสำคัญ* · `TestsetPanel.tsx:17-24` อธิบายว่าทำไมต้องมี test set ·
  `PoolPanel.tsx:449-452` อธิบายว่า **ทำไม** auto-label ถึงถูกล็อก แทนที่จะ disable เฉย ๆ
  มี product น้อยมากที่ทำถึงขนาดนี้
- **Contrast ของตัวอักษร** — ทุก token ผ่าน AA แบบมีที่เหลือ: `--text` 14.9:1,
  `--muted` 6.7:1, `--faint` 5.2:1 บน `--surface` มีคนตั้งใจทำมาแล้ว
- **Focus ring** (`globals.css:106-110`) — 2px สี `--brand` ที่ 10.7:1 เทียบพื้นหลัง,
  offset 2px, ใช้ `:focus-visible` ทั้งระบบ ผ่านแม้แต่เกณฑ์ AAA เรื่อง focus appearance
- **`prefers-reduced-motion`** รองรับทั้งระบบ (`globals.css:625-631`)
- **`LearningCurve.tsx`** เป็นจุดสูงสุดด้าน accessibility ของ codebase นี้: `role="img"`
  พร้อม label จริง, มี **table view** ของข้อมูลชุดเดียวกัน, มี direct label ปลายเส้น,
  *และ* มี legend — ไม่เคยใช้สีอย่างเดียวบอกความหมาย
- **Native windowing** ด้วย `content-visibility` (`globals.css:432-434`) แทน virtualization
  library — 50,000 cell โดยไม่เพิ่ม dependency
- **`Soon`** (`ui.tsx:143-153`) — feature ที่ยังไม่ทำ มองเห็นได้แต่กดไม่ได้ และบอกเหตุผล
  ตรงไปตรงมาและหาไม่ค่อยได้

## 3. สิ่งที่ต้องแก้

ระดับความรุนแรง: **P0** = ผู้ใช้ทำงานไม่สำเร็จ · **P1** = ตก WCAG AA · **P2** = ผิด best
practice หรือทำให้ทำงานช้าลง

### P0 — ตัวบล็อก

#### F-01 · วาด/ย้าย/ปรับขนาด/ลบกล่อง ด้วยคีย์บอร์ดไม่ได้เลย
**WCAG 2.1.1 Keyboard (A) · 2.5.7 Dragging Movements (AA) — ตก**
`components/BoxCanvas.tsx:167-232`

การ label ทั้งหมดผูกกับ `onPointerDown/Move/Up` บน `<div>` ที่ focus ไม่ได้และไม่มี role
ไม่มีทางเลือกแบบ "คลิก–คลิก" แทนการลาก, เลือกกล่องด้วยคีย์บอร์ดไม่ได้ (ปุ่ม `Delete` ที่
`p/[id]/page.tsx:113-119` ทำงานได้ *หลังจาก* ใช้เมาส์เลือกแล้วเท่านั้น) และขยับหรือย่อขยายไม่ได้

ผู้ใช้ที่ใช้คีย์บอร์ดอย่างเดียวหรือใช้ switch device **label ภาพไม่ได้แม้แต่ภาพเดียว**
เพราะเป็นฟังก์ชันหลักของ product จึงอ้าง partial conformance ไม่ได้ด้วย

**วิธีแก้** ทำโหมดวาดแบบสองคลิกให้เป็นทางเลือกระดับเดียวกัน ไม่ใช่ของสำรอง:
canvas เป็น `tabIndex={0}` + `role="application"` + `aria-label` · `Tab` วนเลือกกล่อง ·
ลูกศรขยับกล่องที่เลือกทีละ 1px (`Shift` = 10px) · `Alt`+ลูกศร = ย่อขยาย ·
`Enter` วางจุดเริ่ม กด `Enter` อีกครั้งปิดกล่อง · `Delete` ลบ
แล้วประกาศคลาสและพิกัดของกล่องที่เลือกผ่าน live region พร้อมแสดง caret บนจอ
เพื่อตอบคำถาม "ตอนนี้ฉันอยู่ตรงไหน"

**วิธีแก้** แยก token ออกจากกัน ให้ `--line` เป็นขอบของ *สิ่งที่โต้ตอบได้* ใช้ค่า
**`#6079a4`** — วัดได้ 3.95:1 บน `--surface`, 3.63:1 บน `--surface-2`, 3.20:1 บน
`--surface-3`, 4.44:1 บน `--bg-deep` จึงผ่าน 3:1 บน **ทุก** พื้นผิวในระบบ
ส่วนค่าเดิมที่มืดกว่าย้ายไปเป็น `--line-soft` ใช้กับเส้นคั่นและขอบการ์ดเท่านั้น
และ state ที่ถูกเลือกต้องมีขอบ 3:1 หรือมีสัญลักษณ์กำกับ ไม่ใช่พื้นขาวจาง 6%

#### F-03 · shortcut ปุ่มเดียวปิดไม่ได้
**WCAG 2.1.4 Character Key Shortcuts (A) — ตก** · `p/[id]/page.tsx:78-135`

`N P S C A ? 1-9 Esc Delete Backspace` ผูกอยู่ที่ระดับ `window` ตัวกันมีอย่างเดียวคือ
มันจะไม่ทำงานตอนอยู่ในช่องกรอก (`p/[id]/page.tsx:81`) ซึ่ง **ไม่ใช่** ข้อยกเว้น
"ทำงานเฉพาะตอน component นั้น focus" ตามมาตรฐาน เพราะ shortcut ยัง live ทั้งหน้า
และไม่มีทั้งการ remap และปุ่มปิด — คนที่ใช้ speech input (พูดว่า "press S", สั่งงานด้วยเสียง)
จะยิงคำสั่งพวกนี้ตลอดเวลา

**วิธีแก้** เพิ่มสวิตช์ *Keyboard shortcuts: on/off* เก็บค่าไว้ วางข้าง *Plain language*
และแสดงใน `ShortcutsDialog` — สำหรับ product นี้การตั้งค่าเริ่มต้นเป็น off ถือว่าผิด
แค่ "หาเจอและปิดได้" ก็พอผ่านเกณฑ์แล้ว

#### F-04 · กด `Enter` บนลิงก์ กลายเป็นสั่ง save แทนที่จะไปตามลิงก์
**WCAG 2.1.1 (A) — ตก** · `p/[id]/page.tsx:90-98`

```js
if (e.key === "Enter" && el?.tagName === "BUTTON") return;   // ยกเว้นแค่ BUTTON
```

focus ที่ลิงก์ "CT-Flow / ชื่อโปรเจกต์" บน app bar (`:143`) แล้วกด `Enter`:
handler จะ `preventDefault()` แล้วเรียก `saveLabel()` ลิงก์ไม่เคยพาไปไหน
กระทบ `<a>`, `<summary>` และทุกอย่างที่เป็น `role="link"`

**วิธีแก้** ยกเว้นทุก element ที่โต้ตอบได้ ไม่ใช่ hardcode ชื่อ tag:
`if (el?.closest("a,button,[role=button],[role=link],summary")) return;`

### P1 — ตก WCAG AA

#### F-05 · tab ที่ไม่ได้เป็น tab
**WCAG 4.1.2 Name, Role, Value (A) — ตก** · `p/[id]/page.tsx:155-172`

มี `role="tablist"` และปุ่ม `role="tab"` 5 ตัว แต่ไม่มี `role="tabpanel"` เลย
ไม่มี `aria-controls` ไม่มี `id` บน panel ใด ๆ และไม่มีทั้ง roving tabindex และ
การเดินด้วยลูกศร screen reader จะอ่านว่า "tab 1 of 5" แล้วเจอ landmark
ที่ไม่มีความสัมพันธ์อะไรกับมันเลย

หนักกว่านั้น ปุ่มลูกศร **ถูกยึดไปแล้ว** โดยตัวเลื่อนภาพ (`:120-122`)
ปุ่มเดียวที่ผู้ใช้ screen reader จะกดเพื่อสลับ tab จึงกลายเป็นการเปลี่ยนภาพแทน

**วิธีแก้** เลือกทางใดทางหนึ่ง: implement pattern ให้ครบจริง (`aria-controls`, `id`,
`role="tabpanel"` + `tabIndex={0}`, roving tabindex, ลูกศรทำงานเฉพาะใน tablist และ
กันไม่ให้ไหลไป handler ระดับ window) **หรือ** ถอด ARIA ออกแล้วทำให้มันเป็นสิ่งที่มันเป็นจริง ๆ
คือ `<nav>` ที่มี `aria-current="page"` — ทางหลังง่ายกว่า ซื่อตรงกว่า และ **คืนปุ่มลูกศร
ให้ canvas ไปใช้ตาม F-01**

#### F-06 · modal ไม่กัก focus ไม่คืน focus และมีตัวหนึ่งไม่ได้เป็น dialog ด้วยซ้ำ
**WCAG 2.4.3 Focus Order (A) · 4.1.2 (A) — ตก**

| Dialog | `role` | `aria-modal` | Esc | กัก focus | คืน focus |
|---|---|---|---|---|---|
| `Confirm.tsx:37` | alertdialog | มี | มี | **ไม่มี** | **ไม่มี** |
| `DirPicker.tsx:52` | dialog | มี | มี | **ไม่มี** | **ไม่มี** |
| `ShortcutsDialog.tsx:60` | dialog | มี | มี | **ไม่มี** | **ไม่มี** |
| `CreateDialog` (`page.tsx:330`) | **ไม่มี** | **ไม่มี** | **ไม่มี** | **ไม่มี** | **ไม่มี** |
| overlay ซูมภาพ (`ReportPanel.tsx:161`) | **ไม่มี** | **ไม่มี** | **ไม่มี** | **ไม่มี** | **ไม่มี** |

กด Tab จากในกล่องใดก็ได้ focus จะเดินออกไปหน้าเว็บที่อยู่หลัง scrim ซึ่งยังกดได้อยู่เต็ม ๆ
พอปิดกล่อง focus ไปกองที่ `<body>` — ผู้ใช้หลุดตำแหน่งทั้งหมด

`CreateDialog` กับ overlay ซูมเป็น `<div>` เปล่า ๆ screen reader ไม่มีทางรู้ว่ามี dialog เปิด
และ `CreateDialog` **ปิดด้วยคีย์บอร์ดไม่ได้เลย** (scrim ปิดได้ด้วยการคลิกเท่านั้น
ส่วน `Escape` listener ที่อีกสามตัวมี ตัวนี้ไม่เคยถูกใส่)

**วิธีแก้** เขียน hook เดียว `useDialog(ref, onClose)` — Esc, กัก focus, คืน focus,
ใส่ `inert` ให้หน้าหลัง — แล้วให้ทั้ง 5 ตัวใช้ร่วมกัน
ตามบันไดของ house style ควรลอง native `<dialog>` + `showModal()` ก่อน:
ได้ทั้งการกัก focus, Esc, top layer และ `::backdrop` มาฟรีในทุก browser ที่แอปนี้รองรับ

#### F-07 · สถานะใน gallery บอกด้วยสีอย่างเดียว
**WCAG 1.4.1 Use of Color (A) — ตก** · `panels/GalleryPanel.tsx:148`

จุดสีขนาด 9px เป็นตัวบอก "by hand / by model / test set / unlabeled"
**ตัวเดียวในแต่ละ cell** ส่วน legend ที่ `:139` เขียนอธิบายเป็นประโยค
ซึ่งช่วยคนที่แยกสีไม่ออกไม่ได้ และสีเทา (`unlabeled` ใช้ `--line`) อยู่ที่ **1.55 : 1**
เทียบพื้น cell คือแทบมองไม่เห็นสำหรับทุกคน

**วิธีแก้** ให้แต่ละสถานะมีสัญลักษณ์ควบคู่กับสี (✓ = คนทำ · หุ่นยนต์ = โมเดลทำ ·
เป้า = test set · วงแหวนเปล่า = ยังไม่ label) และใส่สถานะลงใน accessible name ของ cell:
``aria-label={`${file} — labeled by hand`}`` ของแถม: filter chip จะกลายเป็น legend
ที่สอนสัญลักษณ์ไปในตัว

#### F-08 · tooltip ปิดไม่ได้ และสร้าง tab stop ที่ว่างเปล่า
**WCAG 1.4.13 Content on Hover or Focus (AA) — ตก** · `lib/ui.tsx:89-96`

`Tip` เป็น `<span tabIndex={0}>` ที่ไม่มี role และไม่มีชื่อ ส่วนตัว `role="tooltip"`
ก็ไม่เคยถูกอ้างด้วย `aria-describedby` เกิดปัญหา 3 อย่าง:

1. **ปิดไม่ได้** — ไม่มี `Escape` handler ซึ่งเกณฑ์ 1.4.13 บังคับไว้
2. **tab stop ว่าง** — span focus ได้แต่ไม่ประกาศอะไรเลย
3. **tab stop ซ้อน** — ที่ใดที่ `Tip` ครอบ control จริง (`page.tsx:257` ปุ่ม *Claim*)
   ผู้ใช้ต้องกด Tab สองครั้งเพื่อไปถึงปุ่มเดียว

**วิธีแก้** เอา `tabIndex` ออกจากตัวครอบ · ใส่ `aria-describedby` ที่ตัวลูกให้ชี้ไป `id`
ของ tooltip · แสดงเมื่อ `:hover`/`:focus-within` ของตัวลูก · เพิ่ม `Escape` ตอนแสดงอยู่
ส่วนกรณี `Term`/`HelpDot` ที่ไม่มี control อยู่ข้างใน ให้ใช้ `<button type="button">`
เป็นตัวยึด จะได้เป็น tab stop ที่มีชื่อจริง

#### F-09 · เป้ากดเล็กกว่า 24 × 24 CSS px
**WCAG 2.5.8 Target Size Minimum (AA) — ตก**

- ปุ่ม `×` ลบกล่องขนาด **22 × 22** (`BoxCanvas.tsx:282, 330`) วางที่ `top:-28 right:-8`
  ซึ่งห่างจากมือจับย่อขยายมุมขวาบนไม่กี่ px — เป้าเล็ก การกระทำทำลายข้อมูล และเพื่อนบ้านชิด
- `input[type=checkbox]` ขนาด **16 × 16** (`globals.css:176`) และใน `.thumb-row`
  (`TestsetPanel.tsx:229`) มันอยู่ในแถวที่กดได้อยู่แล้ว ข้อยกเว้นเรื่องระยะห่างจึงช่วยไม่ได้
  เพราะวงกลม 24px ทับกับเป้าของแถวเอง

**วิธีแก้** `×` เป็น 28 × 28 และย้ายให้พ้นมือจับมุม · checkbox คงขนาดที่เห็น 16px
แต่ขยายพื้นที่กดเป็น 24px ด้วย `::before` ที่ inset -4px (หรือใส่ `padding` ที่ `label.check`)

#### F-10 · ความสูงตายตัวบน chrome ที่มีตัวอักษร

**วิธีแก้** เปลี่ยน `height` เป็น `min-height` แล้วใส่ padding แนวตั้ง — แก้เหมือนกัน 5 selector

#### F-12 · error หน้าตาและการประกาศเหมือน success ทุกประการ

## 4. แผน redesign

เรียงตาม "conformance ที่ได้ ต่อจำนวนบรรทัดที่แก้" แต่ละ phase ปล่อยแยกกันได้และรีวิวแยกกันได้
ไม่มีข้อไหนต้องเพิ่ม dependency · **Phase 1–3 ปิดทุกข้อที่ตก Level A และ AA ใน §3**

### Phase 1 — token กับ chrome (~1 วัน แก้ CSS อย่างเดียว)

คะแนนที่ถูกที่สุดบนกระดาน: ไฟล์เดียว ไม่แตะ logic ของ component และปิดข้อที่กระจายกว้างที่สุด

1. แยก token ของเส้นขอบ:
   ```css
   --line:      #6079a4;  /* ขอบของสิ่งที่โต้ตอบได้ — ต่ำสุด 3.2:1 บนทุกพื้นผิว */
   --line-soft: #223351;  /* เส้นคั่นและขอบการ์ดเท่านั้น */
   --line-hair: #1a2540;  /* เส้นผมภายในการ์ด */
   ```
   แล้วไล่แก้: ปุ่ม, input, select, checkbox, ราง range และ `.swatch` ใช้ `--line` ·
   `.card`, `.card-head`, `.modal-head/foot` ใช้ `--line-soft`
2. state ที่ถูกเลือกและ state ปัจจุบันต้องมี **ขอบ 3:1 หรือสัญลักษณ์** ไม่ใช่พื้นขาวจาง 6%:
   `.swatch[aria-pressed=true]`, `.thumb-row[aria-current=true]`, `.step[aria-selected=true]`
3. `--faint` → `#8a9cc0` (F-16)
4. `height` → `min-height` ที่ `.step`, `.chip`, `.swatch`, `.gallery-held`, `kbd` (F-10)
5. ฟอนต์ฐาน 13.5px → 14px และไม่มี rule ไหนต่ำกว่า 12px (F-21)
6. ลบ `overflow-x: hidden` แล้วแก้สิ่งที่ล้นซึ่งมันเคยปิดบังอยู่ (F-17)

**เกณฑ์ปิดงาน** axe-core ไม่รายงาน contrast violation เลย · bookmarklet 1.4.12 ไม่ตัดข้อความ
ที่ไหน · ที่ความกว้าง 320px ไม่มี scroll แนวนอน

### Phase 2 — คีย์บอร์ดและ focus (~3 วัน — งานจริงอยู่ตรงนี้)

1. **`useDialog(ref, onClose)`** — Esc, กัก focus, คืน focus, `inert` ให้พื้นหลัง
   แล้วเดิน `Confirm`, `DirPicker`, `ShortcutsDialog`, `CreateDialog` และ overlay ซูม
   ผ่านตัวเดียวกัน · สองตัวหลังต้องได้ `role="dialog"` + `aria-modal` จริง ๆ ด้วย
   ลอง native `<dialog>.showModal()` ก่อน — ได้ hook นี้เกือบทั้งตัวมาฟรี (F-06)
2. **แก้กล่องด้วยคีย์บอร์ดใน `BoxCanvas`** (F-01) แบบที่เข้ากับโมเดลเดิม: canvas เป็น
   `tabIndex={0}` · `Tab`/`Shift+Tab` วนกล่อง · `Enter` บน canvas ว่างวาง caret,
   ลูกศรเลื่อน, `Enter` อีกทีปิดกล่อง · เมื่อเลือกกล่องอยู่ ลูกศร = ขยับ, `Alt`+ลูกศร = ย่อขยาย
   (`Shift` = ×10) · `Delete` = ลบ · ทุกการเปลี่ยนแปลงประกาศผ่าน live region แบบ polite
   เช่น `"person, 412×88 at 120,340"`
   ข้อนี้ปิด 2.5.7 ไปด้วยในตัว เพราะการลากมีของเทียบเท่าที่ไม่ต้องลากแล้ว
3. **แก้ shortcut** — ยกเว้นทุก element ที่โต้ตอบได้จาก guard ของ `Enter` (F-04) ·
   เพิ่มสวิตช์เปิด/ปิดและแสดงใน `ShortcutsDialog` (F-03)
4. **tab** — เลือกทางที่ซื่อตรง: ถอด `role="tablist"`/`role="tab"` เป็น `<nav>` +
   `aria-current="page"` ซึ่งคืนปุ่มลูกศรให้ canvas และกำจัด tabpanel ผีไปพร้อมกัน (F-05)
5. **skip link** (F-15), **`<h1>` + card title เป็น `<h2>`** (F-13), title ต่อ route (F-14)

**เกณฑ์ปิดงาน** ถอดเมาส์ออก แล้วทำครบหนึ่งรอบ: label → save → evaluate → เปิด report
นี่คือแบบทดสอบ ต้องรันจริงก่อนปิด phase

### Phase 3 — status, label และขนาดเป้ากด (~1.5 วัน)

1. แยก `status` เป็น `{ text, tone }` · error ไป `.note bad` + `role="alert"` ·
   success อยู่ที่เดิมแบบ polite · เติม `role="alert"` ให้กล่อง error สี่จุดที่ยังไม่มี (F-12)
2. ใส่ label ให้ช่องโฟลเดอร์ · ย้ายข้อความช่วยเหลือไป `aria-describedby` (F-11)
3. ปุ่ม `×` เป็น 28px และย้ายให้พ้นมือจับมุม · พื้นที่กด checkbox เป็น 24px (F-09)
4. รื้อ `Tip`: ตัวครอบไม่เป็น tab stop, `aria-describedby` ที่ตัวลูก, Esc ปิดได้ (F-08)
5. สัญลักษณ์สถานะใน gallery + ใส่สถานะลงใน accessible name (F-07)
6. guard งานที่ยังไม่ save (F-19) · `Escape` ยกเลิก rename (F-20) · เอา emoji ออกจาก
   `<option>` (F-18) · ใส่ชื่อไฟล์ใน `alt` ของ canvas (F-24)

**เกณฑ์ปิดงาน** axe-core สะอาดทั้ง 5 panel · รัน NVDA หนึ่งรอบบน labeling loop
โดยไม่ได้ยินคำว่า "unlabeled" หรือ "clickable" ลอย ๆ

### Phase 4 — ความหนาแน่นและการอ่านออก (~2 วัน · ไม่บังคับแต่แนะนำ)

แอปนี้ถูกจูนมาสำหรับ developer หน้าจอ 27 นิ้ว แต่ผู้ใช้จริงคือคนทำ QC หกชั่วโมง
บนเครื่องหน้างานความละเอียด 1366×768

- สวิตช์ **Comfortable / Compact** วางข้าง *Plain language* ขับ `--s*` และ scale ฟอนต์
  จาก `[data-density]` attribute เดียว · ค่าเริ่มต้นคือ Comfortable: ฐาน 16px,
  control สูง 40px, ต่ำสุด 12.5px
- **ธีมสว่าง** — chrome สีเข้มเป็นภาระเมื่ออยู่ใต้แสงโรงงาน · สีทุกตัวอยู่ใน token อยู่แล้ว
  งานนี้จึงเป็น `@media (prefers-color-scheme: light)` หนึ่งบล็อกบวกตัว override ด้วยมือ
  ซึ่งเป็นโครงที่ token ชุดนี้ถูกสร้างมาเพื่อรองรับตั้งแต่แรก
- ขยายพื้นที่กด: แถวคิวเป็น 44px, gallery cell ต่ำสุด 120px

### Phase 5 — หน้าจอภาษาไทย (~3 วัน · คุ้มที่สุดในโลกจริง)

`IBM Plex Sans Thai` ถูกดาวน์โหลดทุกครั้งที่โหลดหน้า (`layout.tsx:22`) อยู่แล้ว
โดยที่ไม่มีตัวอักษรไทยสักตัวถูก render — คนที่เครื่องมือนี้ถูกสร้างให้ใช้ อ่านภาษาไทย

- ฟังก์ชัน `t()` หนึ่งตัว กับไฟล์คู่ `messages.{en,th}.ts` · **ไม่ต้องมี i18n library** —
  จำนวน string อยู่ระดับร้อยต้น ๆ และ `Intl` ครอบคลุมเรื่องพหูพจน์กับวันที่แล้ว
  (เพิ่ม `next-intl` ต่อเมื่อจำเป็นต้องแยก route ตาม locale จริง ๆ)
- `<html lang>` ต้องเปลี่ยนตามภาษาที่เลือก ตอนนี้ hardcode เป็น `"en"` (`layout.tsx:11`)
  และ `lang` ที่ผิดทำให้ screen reader ออกเสียงผิดทุกคำ (**3.1.1**)
- ภาษาไทยไม่เว้นวรรคระหว่างคำ — ต้องทดสอบ `.truncate` และทุก `min-height` จาก Phase 1
  กับข้อความไทยจริงก่อนปล่อย
- สวิตช์ *Plain language* (`p/[id]/page.tsx:185`) กับสวิตช์ภาษาเป็นคนละแกน
  ต้องแยกเป็นคนละ control

### สิ่งที่ไม่อยู่ในขอบเขต

- **ไม่เพิ่ม UI framework, component library หรือ CSS-in-JS** — ทุกข้อข้างบนทำได้ด้วย
  token และ stdlib ที่มีอยู่แล้ว · วันนี้ `frontend/package.json` มี 3 dependency
  ให้มันอยู่ที่ 3 ต่อไป
- **ไม่รื้อ brand** — เอกลักษณ์ Connected Tech, สีฟ้า cyan, chrome ทรงแคปซูล และ
  radial glow อยู่ครบ · Phase 1 เปลี่ยน contrast ไม่ได้เปลี่ยนบุคลิก

## 5. วิธีตรวจ

ไม่มี frontend test และ `frontend.yml` ตรวจแค่ import, type และ build — ซึ่ง**ไม่จับ
ข้อไหนในเอกสารนี้เลยสักข้อ** ก่อนปิดแต่ละ phase:

```bash
cd frontend && npx tsc --noEmit && npm run build   # ต้องเขียวตลอด
```

แล้วตรวจด้วยมือ ต่อ phase:

1. **axe DevTools** บน `/`, `/entry/login` และทั้ง 5 panel ของ `/p/{id}` —
   เกณฑ์คือ critical เป็นศูนย์ และ serious เป็นศูนย์
2. **ถอดเมาส์** แล้ว label ภาพ, save, เพิ่มภาพ test, evaluate, เปิด report, ซูมภาพ, ปิด
   ถ้ามีขั้นไหนทำไม่ได้ แปลว่า Phase 2 ยังไม่เสร็จ
3. **NVDA หรือ VoiceOver** หนึ่งรอบบนเส้นทางเดียวกัน — ฟังหา element ที่ถูกอ่าน
   โดยไม่มี role หรือไม่มีชื่อ
4. **viewport 320px และ zoom 200%** — ไม่มี scroll แนวนอน ไม่มีอะไรถูกตัด
5. **bookmarklet 1.4.12 text-spacing** — ต้องไม่มีอะไรถูกตัด

การเพิ่ม axe แบบ headless เข้า `frontend.yml` คุ้มค่าเมื่อ Phase 1 ลงแล้ว — มันเป็น
การตรวจอย่างเดียวที่จับ regression ทั้งตระกูลนี้ได้ และไม่ต้องมี test suite มาก่อน
